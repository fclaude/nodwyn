\part{How it was built, and what is next}

\chapter{Bootstrap, then self-host}

\nodwyn{} was not bootstrapped by hand. The first version was built with
another coding-agent harness, which this book does not name, working from
\file{SPEC.md} and \file{plan.md}. Its job was the smallest \nodwyn{} that
could do real work on its own repository: an append-only log, a minimal
Scheme kernel, the guard with the first checkers, file and shell
primitives, a model client, the loop, a line-mode front-end, and a few
repository tools written in Scheme. That was promoted as
\code{v0.1-bootstrap} on 2026-09-21, the day after the first commit.

From then on \nodwyn{} took over: development runs the last promoted
binary, \code{nodwyn-stable}, against this repository. The external harness
did not disappear. \adr{16} allows a fallback when a task is faster another
way, provided it is said, and \file{plan.md} records the phases where it was
used.

\section{Why this order}

Three deliberate deviations from the spec's numbered build order:

\begin{itemize}
\item \textbf{The log first, not last.} Invariant~1 makes it the source of
  truth and every later phase says ``logged''. A small JSONL writer on day
  one beats retrofitting six phases.
\item \textbf{A walking-skeleton loop right after the guard.} The security
  phases are then tested against a real loop, not a mock.
\item \textbf{A minimal kernel, grown later.} To self-host you need a
  working loop before a complete interpreter; the language grew afterwards,
  behind a conformance suite.
\end{itemize}

\section{Two binaries, always}

\file{bin/nodwyn} is the working-tree build.
\file{\textasciitilde/.local/bin/nodwyn-stable} is the last \emph{promoted}
build. Development runs \code{nodwyn-stable}; \nodwyn{} never edits itself
through the binary being edited, so a broken tree can never strand you.
Promotion (\code{make promote}) refuses a dirty tree, runs the acceptance
suite and a self-check\,---\,the candidate completes a scripted session
against a fake model and replays its own log\,---\,then swaps the binaries
and keeps the previous one as \code{.prev}. The stable binary's version is
the commit it was built from. Until 2026-09-30 each promotion also created
a tag, \code{v0.N-name}; \adr{13} was amended to drop them, because a
phase name added nothing the commit did not say.

compensating controls. Each was retired by the phase that built the real
thing, or kept as defense in depth:

\section{The friction log}

When \code{nodwyn-stable} gets in the way, the rule is: hand-edit, and write
one line in the friction log, \file{docs/friction.md}. That file is the backlog for the
front-ends and for memory, and it paid for itself early: the first
self-hosting run showed the model rewriting a 400-line file to change one
line; the entry became \code{fs-edit} the same afternoon, and the second run
took a third of the tool calls.
