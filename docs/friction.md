# Friction log

Where `nodwyn-stable` got in the way while building nodwyn (ADR 15). One line
per observation, newest first. Reviewed at every promotion; the top items
become side-work in the next phase.

Format: `date · session · what happened · what it cost · idea`

- 2026-09-30 · stable install · `make build` has no webview tag, so a stable installed the promote way answered the desktop launcher (`nodwyn-stable app`, no terminal) with the browser fallback instead of a window · the app looked as if it had not started · **resolved: promote builds `make build-webview` (a pkg-config shim maps webkit2gtk-4.0 to 4.1) and refuses an installed binary without `-tags=webview`; without WebKitGTK it installs the browser build and says so**
- 2026-09-27 · SWE-bench harness · output was never capped: window.output_reserve only sized the context, and Qwen thinking bursts reached 17k tokens (0.2% of replies over 8k), enough to overflow a context sized to the window · a prompt at high water plus a long reply could be cut by the server · **resolved: output_reserve (16k by default) caps every reply (num_predict / max_completion_tokens, recipe v8); a cut reply is noted, and ask-model asks again, briefer, at most twice**
- 2026-09-27 · SWE-bench harness · a run whose strategy redefined agent-turn got no plan once the gate moved into Scheme, so its first write was refused; and the planner was offered every tool, so a tool-call answer counted as no plan · every custom strategy broke under `nodwyn run` · **resolved: the host runs `turn`, which plans first in a run whatever agent-turn is; the planner is asked with no tools (`model-turn` options, recipe v7)**
- 2026-09-27 · SWE-bench harness · a turn that ended on a folded reviewer's reply was recorded as limited, not completed · run statuses misreported · **resolved: completion is judged by the reply the conversation still shows (eece625)**
- 2026-09-27 · SWE-bench harness · the planner once answered with thinking only, and a run requires a nonempty plan, so the task ended before any work · one benchmark task in about 85 lost outright · **resolved: an empty draft is asked for again up to twice, noted in the log; an empty revision keeps the best plan**
- 2026-09-27 · SWE-bench tuning · writes to /tmp were refused, so the model put throwaway scripts in the repository or wrote them through the shell · stray files in the patch, and turns spent working around the pin · **resolved: each session has a scratch directory outside the repository, writable without prompts and TMPDIR for commands (ADR 28)**
- 2026-09-26 · SWE-bench harness · L1 took any three dot-joined words of 8+ characters for a JWT, so Django test labels such as `model_fields.test_jsonfield.TestQuerying` were secrets: shell-exec denied the test runs, and a judge request quoting one was refused as an unbound secret, which ended the turn · two of fifteen Jev-verify tasks lost outright, and denied test commands in two other variants · **resolved: a JWT must start with an encoded JSON header and payload (`eyJ…` `.ey…`)**
- 2026-09-26 · SWE-bench harness · the model sent whole command lines as shell-exec's cmd ("python3 -m pip", "cd /testbed && git log"), and exec answered only "not found" · about 4% of shell calls failed and cost the model a turn to recover · **resolved: such a failure now says how to split cmd and args, and names sh -c for pipes**
- 2026-09-26 · SWE-bench harness · the manual said `nodwyn run start`, but only status/stop/resume were subcommands, so the documented command failed with a usage error · a harness wired from the manual could not start runs · **resolved: `nodwyn run start` is accepted as the explicit form of `nodwyn run`**
- 2026-09-26 · SWE-bench harness · Qwen occasionally wrote tool-call markup the server's parser rejected, even in the planner's tool-less request, and one failed request ended the whole turn · whole benchmark tasks lost to one bad sample · **resolved: a failed model request is retried twice with backoff, each failure logged as a note**
